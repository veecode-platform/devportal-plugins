# VeeCode DevPortal Plugins

This repository hosts Backstage plugins developed by VeeCode for [VeeCode DevPortal](https://docs.platform.vee.codes/devportal/), an open-source Backstage distribution for Internal Developer Portals (IDP).

Plugins are published as dynamic plugins, one OCI image per plugin on `quay.io/veecode`, through the export overlay (`devportal-plugin-export-overlays`); npm publishing is retired. They are built for VeeCode DevPortal and Red Hat Developer Hub (RHDH).

## Workspaces

Each workspace groups related plugins and has a development harness sized to its package roles.

The workspaces are the directories under [`workspaces/`](workspaces/); each has an `AGENTS.md`
that says what it contains and how to prove it. That directory is the inventory, so this
file does not keep a second list.

## Getting Started

Each workspace is self-contained. Navigate to a workspace and run:

```sh
cd workspaces/<name>
yarn install
yarn start          # Start the Backstage hosting app
```

To build and test:

```sh
yarn tsc            # TypeScript check
yarn build:all      # Build all packages
yarn test:all       # Run all tests
yarn lint:all       # Lint all files
```

## Building and Publishing

Some workspaces provide a Makefile. Use the workspace's `AGENTS.md` for its commands.

To load a workspace's export in the local DevPortal runner (proof 2), run `yarn dev:dynamic`
inside the workspace and follow the Compose command it prints (`devportal-local`).

## Reference Implementation

The workspace template (`scripts/workspace-template/`) is the source for new
workspace scaffolding. The existing **dummy** workspace (`workspaces/dummy/`) remains
the accumulated reference fixture and is not regenerated by the scaffold. It demonstrates:

- Frontend plugin with full-page view, entity cards, and entity tabs
- Backend plugin with HTTP API, service architecture, and dependency injection
- Complete test suite (plugin unit tests, hosting app wiring tests)
- Dynamic plugin export with `yarn dev:dynamic`, proven in the `devportal-local` runner
- Standardized Makefile with build and packaging targets

When creating a new workspace, run `yarn create-workspace <name> --role <role>` and
follow the generated workspace's `AGENTS.md`. The command renders the workspace shell
from the template, then runs `yarn install`, creates the product package with
`backstage-cli new` (the official Backstage template for the role), pins every
`@backstage/*` dependency to the host line with `versions:bump`, and formats the tree.
It needs network access and takes a few minutes; `--shell-only` renders just the
shell for an offline look at the layout.

## Background

This monorepo replaces the previous multi-repository setup at [veecode-platform/backstage-plugins](https://github.com/veecode-platform/backstage-plugins) and [veecode-platform/dynamic-plugins](https://github.com/veecode-platform/dynamic-plugins). The structure is based on [backstage/community-plugins](https://github.com/backstage/community-plugins) and [redhat-developer/rhdh-plugins](https://github.com/redhat-developer/rhdh-plugins).
